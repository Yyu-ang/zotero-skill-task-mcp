# 内建笔记完成判定

每个技能组可单独配置 `completionRule`，让插件根据文献已有的 Zotero 内建笔记判断是否完成。规则只决定是否继续派发，不会修改笔记标题、补写标签或评价内容质量。

## 使用

1. 将交付物设为“内建笔记”或“Markdown → 笔记”。
2. 在“已有笔记完成判定”中启用规则，添加至少一个正向条件。
3. 选择全部满足（AND）或任一满足（OR），按需添加排除条件和字数要求。
4. 在 Zotero 个人文库中选中文献，点击“检查当前选中文献”查看匹配的笔记和条件编号。预览最多检查前 20 篇，只读取数据，并使用尚未保存的当前表单范围和规则。
5. 保存技能组并重新扫描。已有结果会进入“已完成”，来源为“已有笔记”；其他文献仍按材料要求进入待领取或等待材料。

## 匹配语义

| 项目 | 规则 |
| --- | --- |
| 检查范围 | 当前文献的直接子笔记；忽略已删除、其他文献和其他文库的笔记 |
| 标签 `tag` | 读取笔记自身标签，支持 `equals`；不读取父文献标签 |
| 标题 `title` | 使用 Zotero 返回的笔记标题，支持 `equals`、`contains`、`startsWith` |
| 正文 `text` | 使用笔记可见文本，支持 `equals`、`contains`、`startsWith`；可用于识别自定义文本标记 |
| 文字比较 | Unicode NFC 归一化、连续空白合并、首尾空白去除；区分大小写，值按普通文字解释 |
| 正向条件 | `all` 要求同一篇笔记满足全部条件；`any` 要求同一篇笔记满足任一条件 |
| 排除条件 | 一篇笔记命中任何排除条件后，不能使任务完成；不排除同一文献下其他合格笔记 |
| 内容要求 | 默认要求至少 1 个非空白字符；标题也计入，HTML 标签、注释、脚本、样式和隐藏内容不计入 |
| 多篇匹配 | 任意一篇合格即可；记录修改时间最新的匹配笔记，时间相同按笔记 Key 稳定选取 |
| 读取异常 | 不能把读取失败当成“没有笔记”；未能确认匹配时阻止派发并报告错误 |

例如，条件是“标签等于 `result-ready` **且**标题开头为 `实验记录`”时，必须有一篇笔记同时具备这两个特征。两篇不同笔记各满足一个条件不会被合并判断。

`text` 是整篇可见文本，包含标题；并非 HTML 源码或 CSS 选择器。隐藏注释不能用作完成标记。第一版不提供正则表达式、跨笔记组合、附件内容检查或业务专用预设。

## 生命周期

| 时机 | 行为 |
| --- | --- |
| 扫描 | 先判断已有笔记；匹配即记录完成，无需等待 PDF 材料 |
| 领取前 | 重新检查，避免扫描之后新增的笔记导致重复领取 |
| 任务处理期间 | 后台笔记变化不终止已领取任务；任务保留领取时的规则 |
| 提交前 | 按领取时的规则再检查；匹配则复用已有笔记，不创建第二篇笔记 |
| 笔记变更 | 新增、编辑、删除会触发相关条目重查；原先由规则认定完成但已不匹配的记录可回到待领取或等待材料 |
| 规则编辑 | 保存后重新扫描应用；尚未领取的任务按当前规则判断 |
| 关闭规则 | 停止这项检查，保留已经记录的完成项 |

已取消任务不会自动恢复；由 AI 实际提交完成的任务不会因规则变化自动重做。插件自身并发的扫描、领取和提交按同一技能组及文献协调，避免同时创建任务或重复写入。不同技能组仍有各自的任务记录；这是结果存在性判定，不是多个进程或多台 Zotero 的分布式互斥。

任务详情显示完成来源、笔记 Key 和成功提交次数，并可直接定位笔记。“识别时间”表示插件首次确认已有结果的时间，不表示笔记的创建时间。识别已有结果的成功提交次数为 0，不计入 AI 新完成数量。旧任务保留原有完成记录和计数。

## MCP 配置

`skilltask_inject_skill` 接收可选的结构化 `completionRule` 字段，和界面使用同一套校验。`SKILL.md` 内容不参与自动推断；没有这个字段时沿用原有派发方式。

以下配置表示：同一篇笔记必须具有标签 `result-ready`，标题以 `实验记录` 开头，排除带 `draft` 标签的笔记，并至少有 20 个非空白字符。

```json
{
  "completionRule": {
    "enabled": true,
    "type": "builtin-note",
    "match": {
      "operator": "all",
      "conditions": [
        { "field": "tag", "operator": "equals", "value": "result-ready" },
        { "field": "title", "operator": "startsWith", "value": "实验记录" }
      ],
      "exclude": [
        { "field": "tag", "operator": "equals", "value": "draft" }
      ],
      "requireContent": true,
      "minContentLength": 20
    }
  }
}
```

这是注入参数中的一个字段，注入时只有技能名称 `name` 和指令 `instruction` 必填，范围、材料和交付物可显式配置，也可使用插件默认值。启用的规则不能有空条件、空匹配值或不支持的比较方式。单组正向或排除条件最多 50 项，匹配值最多 1,000 字符，最少内容长度取 0 至 1,000,000 的整数。

`requireContent: false` 且 `minContentLength: 0` 表示不要求内容长度；如果指定了大于 0 的最少长度，仍执行该长度限制。界面会将这种配置显示为勾选内容要求，并保留原长度；手动取消“要求笔记具有可见内容”时才把最少长度设为 0。

## Beta 范围

本版沿用插件的个人文库扫描范围，仅支持内建笔记交付。规则信息随技能组保存，任务记录新增可选字段以区分完成来源和领取时规则。升级后未配置规则的技能组默认关闭，已有任务无需手工迁移。

测试环境中的规则与任务流程检查不能代替 Zotero 9/10 的实际使用验证。安装 beta 后建议先使用一个小集合，预览匹配情况，再进行正式批量扫描。
